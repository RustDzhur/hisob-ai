# Hisob AI — Дизайн-система и экраны

Источник: ТЗ §4–5. Статус: **ЧЕРНОВИК**. Ниже — спецификация и каркасы (ASCII), а не пиксельные макеты; визуальные макеты в Figma можно сделать по утверждении. Принцип: **каждая кнопка выполняет реальное действие**; если функция ещё не реализована — элемента нет в UI (не «заглушка»), либо он явно помечен бейджем «Скоро» и неактивен с пояснением.

## 1. Токены

**Вывод для реализации** (отклонение от «голых» цветов ТЗ, нужно подтверждение — Q11): исходные цвета используются как **заливки, иконки, индикаторы**. Для **текста и кнопок с текстом** вводятся более тёмные производные: `--blue-600 ≈ #2563EB`, `--success-text #0B6B4E` на `#E6F6F0`, `--warning-text #8A5A00` на `#FDF3DC`, `--danger-text #A02D2D` на `#FBE9E9`, `--ai-text #5A3FD6` на `#EFEBFE` (контраст 5.4–6.2:1, рассчитан). Целевой стандарт — WCAG 2.1 AA. Статус никогда не передаётся только цветом (иконка + текст).

### Типографика
Inter (кириллица) → системный fallback. Основной 14px/20, таблицы 13–14px, вспомогательный 12px, заголовок страницы 22px/28 semibold, секции 18px/24 semibold, KPI-число 28px tabular-nums. **Числа и суммы — `font-variant-numeric: tabular-nums`, выравнивание вправо.** Формат суммы: `1 250 000,50 UZS` (пробел — разряды, запятая — дробная часть; локаль и валюта — Q5/Q7).

### Сетка, радиусы, тени, плотность
Шаг 4px (4/8/12/16/24/32). Радиус: 8 карточки/поля, 6 бейджи, 12 диалоги. Тень только у drawer/диалогов/выпадающих списков; карточки — границей. Режим плотности таблицы: стандартный (44px строка) / компактный (36px) — настройка пользователя.

### Анимация и доступность
Анимации ≤200 мс, уважать `prefers-reduced-motion`. Фокус-кольцо 2px `--blue` всегда видимо. Полная клавиатурная навигация, ARIA через Radix, `lang="ru"`. Тёмная тема не входит в MVP.

## 2. Компоненты (общий набор `components/ui`)

Button (primary/secondary/ghost/danger, loading), IconButton, Input/Textarea/Select/Combobox/DatePicker/MoneyInput (строка → Decimal на сервере), Field (label + hint + inline error), Checkbox/Radio/Switch, **DataTable** (поиск, фильтры-чипы, сортировка, пагинация, выбор строк, колонки, состояния), **StatusBadge**, KpiCard, Tabs, Drawer (проверка документа), Dialog и **DangerDialog** (требует ввода слова-подтверждения или удержания; не закрывается случайным касанием), Toast, Banner (ошибка интеграции, режим MOCK), Skeleton, EmptyState (с реальным CTA), ErrorState (с retry и correlation_id), Avatar, OrgSwitcher, PeriodPicker, SourceLink («откуда число»), AiBadge.

**Обязательные состояния каждого экрана:** loading (skeleton) · empty (объяснение + действие) · error (причина, retry, correlation_id) · success/partial · forbidden (нет права — понятное сообщение, не пустая страница).

### Статусные бейджи (из ТЗ)
`RECEIVED`/`PROCESSING` — серый/синий с анимацией; `NEEDS_REVIEW` — warning; `APPROVED` — синий; `POSTED` — success; `RECONCILED` — success + иконка сверки; `ARCHIVED` — серый; `FAILED`/`REJECTED` — danger; `DUPLICATE` — warning с иконкой копии. Человекочитаемые русские подписи; код статуса — в tooltip.

## 4. Экраны (основные)

### 4.1 Вход / Регистрация / Выбор организации (этап 1)
Карточка по центру: email, пароль, «Войти»; ошибки inline (без раскрытия существует ли email). Регистрация: имя, email, пароль (индикатор требований). После входа: если организаций нет → экран «Создать организацию» (название, ИНН опц., часовой пояс, валюта по умолчанию); если несколько → выбор. Приглашение: страница по одноразовой ссылке (задать пароль → вступить).

### 4.2 Главная
```
[KPI: Деньги на счетах] [Продажи за период] [Расходы] [Просроч. дебиторка] [Стоимость запасов]
 каждая: значение + валюта + период + ссылка «Откуда число» → расчёт/документы
┌ Требует внимания ───────────────────────┐ ┌ Быстрые действия ──────────┐
│ ⚠ 3 документа с низкой уверенностью     │ │ [Загрузить документ]       │
│ ⧉ 1 возможный дубликат                  │ │ [Создать приход]           │
│ ⚠ 5 несверенных платежей                │ │ [Импорт выписки]           │
│ ✖ ошибка интеграции …                   │ │ [✦ Задать вопрос AI]       │
│ ⛔ отрицательный остаток …              │ └────────────────────────────┘
└─────────────────────────────────────────┘
```
Правило: KPI показывает **только реальные данные**; пока данных нет — «—» и пояснение «нет данных за период», не нули и не демо. Пока модули не реализованы, карточки не рендерятся. На этапе 1 — приветствие, статус организации и состав команды (реальные данные).

### 4.3 Документы
Таблица: поиск, фильтры (статус, тип, контрагент, дата, уверенность), сортировка, пагинация. Колонки: тип · номер · дата · контрагент · сумма+валюта · статус · уверенность · автор. Кнопки: «Загрузить» (drag-and-drop + выбор + камера на mobile). Массовые действия — только безопасные (архив, назначить проверяющего).

**Drawer/экран проверки документа** (ключевой экран):
```
┌ оригинал (PDF/изображение, zoom) ──────┬ Извлечённые поля ─────────────────┐
│  [подсветка фрагмента при фокусе поля] │ Тип ▾  Номер  Дата                │
│                                        │ Контрагент [предложено: …, почему]│
│                                        │ ИНН  ✔ формат                     │
│                                        │ Строки: товар | кол-во | ед. | цена│
│                                        │   ↳ сопоставление: предложение+причина│
│                                        │ Итоги: расчёт ✔ / ⚠ расхождение   │
│                                        │ каждое поле: confidence ▮▮▮▯, источник│
├────────────────────────────────────────┴───────────────────────────────────┤
│ Предупреждения: дубликат? необычная цена? закрытый период?                 │
│ [Отклонить] [Распознать заново] [Сохранить правки]  [Утвердить →]          │
└────────────────────────────────────────────────────────────────────────────┘
```
Правка поля фиксируется в аудите (кто, было→стало). «Утвердить» недоступно, пока есть блокирующие ошибки валидации; причина показана рядом. Проведение — отдельное подтверждение.

### 4.4 Склад
Вкладки: Остатки (по складу/товару/ед., фильтр «ниже минимума», «отрицательные») · Движения (журнал, источник → ссылка на документ) · Операции (Приход/Расход/Перемещение/Возврат/Инвентаризация — мастер: шапка → строки → проверка → **подтвердить**; после проведения кнопка превращается в «Сторно»). Карточка товара: SKU, штрихкод, единицы, ИКПУ (если задан), история. Предупреждение о расхождении остатка и журнала — явный баннер.

### 4.5 Контрагенты / Товары и услуги
Таблица + карточка; создание/редактирование drawer-ом; проверка уникальности ИНН/SKU inline; поиск дубликатов при вводе.

### 4.6 Бухгалтерия
Журнал проводок (дата, источник-ссылка, дебет/кредит, сумма+валюта, правило+версия, статус); фильтры по периоду/счёту. Периоды: статус открыт/закрыт, закрытие — DangerDialog. Исправление — «Сторнировать» (не «Редактировать»). Экран и состав проводок **не проектируются до Q9**.

### 4.7 Банк и сверка
Слева — банковские операции (нераспознанные/несверенные), справа — кандидаты совпадений с **объяснением** («сумма совпала, дата ±1 день, референс в назначении»). Действия: подтвердить / отклонить / разбить / объединить; всё в аудит. Импорт: выбор счёта → файл → предпросмотр нормализации → подтверждение; повторный импорт того же файла сообщает «уже импортировано N операций».

### 4.8 Отчёты
Фильтр период/организация/валюта; таблица + раскрытие до первичных документов и операций (drill-down «каждая цифра объяснима»); экспорт — с записью в аудит.

### 4.9 ✦ AI-помощник
Чат; над полем ввода быстрые подсказки; ответ показывает **период, валюту, критерии, список источников** (ссылки), и пометку «данные неполные», если так; кнопки «Открыть документ», «Показать расчёт», «Создать черновик» (черновик → в очередь на утверждение человеком). Режим (Assist/Supervised) виден; Autopilot отсутствует в MVP. Фиолетовый акцент, бейдж «AI» на сгенерированном.

### 4.10 Интеграции
Карточки провайдеров с **честным статусом**: `Не настроено` / `MOCK (тестовые данные, не реальная интеграция)` / `Подключено`. Для Multibank/Faktura.uz/Didox до получения документации — «Ожидает официальной документации и доступов». Журнал синхронизаций, повтор, ошибки с кодом.

### 4.11 Настройки
Организация (реквизиты, часовой пояс, валюта, политика отрицательных остатков — по умолчанию «запрещены»), **Участники и роли** (список, пригласить, сменить роль, приостановить; последний владелец защищён), Журнал аудита (фильтры, экспорт), Безопасность профиля (смена пароля, активные сессии → «Выйти везде»), Уведомления.

### 4.12 Mobile (адаптив ≤768px)
Нижняя навигация (Главная · Документы · Склад · ✦ AI · Ещё). KPI — вертикальные карточки; «Сфотографировать документ» (камера → загрузка → статус); задачи проверки — списком карточек, а не таблицей; остатки — карточки с поиском/сканом штрихкода (если доступно); чат. Сложные таблицы (проводки, сверка) на mobile — только просмотр карточками, редактирование — «откройте на десктопе». Опасные действия — DangerDialog с удержанием/вводом подтверждения, зоны касания ≥44px, расстояние между «Отмена» и опасной кнопкой.

## 5. Тексты и локализация
Интерфейс на русском в MVP-каркасе, строки выносятся в словари с первого экрана (узбекский — Q7). Сообщения об ошибках конкретные и действенные («Не удалось утвердить: не заполнен ИНН контрагента»), без технического жаргона; технические детали — `correlation_id`.
