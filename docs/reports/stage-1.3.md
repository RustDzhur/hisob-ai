# Отчёт: срез 1.3 — журнал аудита в UI, смена пароля, сессии

Дата: 2026-10-10. Среда: сервер Ubuntu 26.04 (Docker, PostgreSQL 16); статические проверки — macOS (Python 3.12 через uv, Node 24). **Этап 1 этим срезом завершён.**

## Что реально работает
- **Журнал аудита** (`GET /organizations/{id}/audit`, право `audit.read`: владелец, админ организации, аудитор): новые события сверху, пагинация (страница/размер ≤100, общее число), фильтры по действию, пользователю (API) и датам «с/по» (границы суток — в часовом поясе организации), список доступных действий. Видны автор, объект, «до/после», correlation_id, IP. События без организации (вход/выход/регистрация) в журнал организации не попадают. Секреты в журнал не попадают (проверено тестом).
- **Смена пароля**: проверка текущего пароля (неверный — 422 и попытка засчитывается в тот же лимит, что и вход: 5 за 15 минут → 429), политика нового пароля, новый ≠ текущему; текущая сессия сохраняется, **все остальные завершаются**; события `auth.password_changed` / `auth.password_change_failed`.
- **Сессии**: список активных сессий (устройство, IP, время, «эта сессия»), завершение любой своей, «выйти на всех устройствах» (включая текущую); чужую сессию завершить нельзя (404). События `auth.session_revoked`, `auth.logout_all`.
- **UI**: страницы «Журнал аудита» (фильтры, таблица/карточки на мобильном, раскрываемые подробности, пагинация, состояния загрузки/ошибки/пусто/нет доступа) и «Безопасность» (форма смены пароля с inline-ошибками, сессии, диалог подтверждения). Пункт «Журнал аудита» виден только при `audit.read`, «Безопасность» — всем.

## Что НЕ реализовано / ограничения
- **Нет экспорта журнала** (в ТЗ экспорт должен аудироваться — делается вместе с экспортом данных). Фильтр по пользователю есть в API, но в UI его нет (только действие и даты).
- События входа/регистрации хранятся без организации и видны только самому пользователю на уровне БД; «журнала безопасности аккаунта» в UI нет.
- Попытки смены пароля делят лимит со входом: подобрав текущий пароль по украденной сессии нельзя, но владелец аккаунта тоже может на 15 минут потерять возможность войти.
- Нет: сброса пароля по почте, подтверждения email, MFA, смены email/имени, удаления аккаунта.
- Журнал читает всё из одной таблицы без архивации и индекса по `action`; при росте нужно будет оптимизировать (этап 9).
- Глазами внешний вид не проверялся; доступность (WCAG) не аудирована инструментами.
- Изменения не закоммичены.
