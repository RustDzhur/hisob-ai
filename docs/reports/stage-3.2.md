# Срез 3.2 — распознавание документов (AI)

## Что сделано
- **Очередь и воркер**: Dramatiq + Redis (очередь `extraction`), отдельный контейнер `worker`. Источник истины о задачах — таблица `ai_job` в PostgreSQL (Redis можно потерять без потери данных). Повторы до 3 раз только для временных ошибок провайдера; задача идемпотентна.
- **Провайдеры** (прямые HTTP-адаптеры, форматы сверены с официальной документацией): OpenAI Responses API (строгая JSON-схема, `store:false`; изображения, PDF, таблицы как текст) и DeepSeek chat completions (режим JSON; **PDF не поддерживается — честная ошибка `provider_unsupported_input`**). Ключи есть только у контейнера `worker`.
- **Строгая схема ответа** (`extra=forbid`): значение, уверенность 0..1, цитата-источник на каждое поле; ответ, не прошедший схему, отбрасывается. Содержимое документа передаётся как недоверенные данные в ограничителях, инструментов у модели нет.
- **Заполнение**: AI заполняет **только пустые** поля, ничего не перезаписывает; невалидные значения (знаки после запятой сверх валюты, не-ASCII цифры, даты) не применяются и показываются отдельно. Контрагент и товары — детерминированное сопоставление (ИНН, название, артикул, штрихкод), автоподстановка только при точном совпадении, остальное — варианты с причиной. Документ **сам не утверждается**.
- **Интерфейс**: панель «Распознавание (AI)» в карточке документа (статус с опросом каждые 3 с, отмена, повтор, подсказки с уверенностью и цитатой, «применить» / «применить все», варианты контрагента), переключатель «Распознать сразу» при загрузке (только если провайдер настроен), метка MOCK для тестового провайдера, тексты на uz/ru/en.
- Суточный лимит распознаваний (`AI_MAX_JOBS_PER_DAY`, 200), аудит: запрос, успех, ошибка, отмена. Права: запуск — `documents.review`.
- Исправление проверки итога: налог, указанный только по документу (не по строкам), раньше давал ложное предупреждение `total_mismatch` — найдено на реальном запросе.

## Основной и запасной провайдер
По решению владельца: основной — **OpenAI**, запасной — **DeepSeek** (`AI_PROVIDER`, `AI_FALLBACK_PROVIDER`). Запасной вызывается **только при отказе основного** (ключ, лимит, недоступность, таймаут, пустой/непонятный/отказной ответ), не параллельно: иначе документ уходил бы двум сторонам без необходимости. Если основной не настроен, работает запасной. Если запасной не умеет тип файла (PDF у DeepSeek) — остаётся ошибка основного. В карточке показывается провайдер, который реально дал результат; в аудите — `fallback_from` и код отказа основного. **Следствие для данных**: при сбое OpenAI документ уходит в DeepSeek (КНР) — см. Q4.

## Ограничения и риски — прочитайте
- Первый ключ OpenAI был отклонён (401); владелец вписал новый, и живой запрос прошёл. **Живой отказ OpenAI → переход на DeepSeek не воспроизводился** (проверено тестами с имитацией отказа).
- **Названия моделей** (`deepseek-flash`, `gpt-6-luna`) задал владелец; я их не подбирал и не гарантирую. Качество распознавания проверено на **одном синтетическом документе**, не на реальных — нужны обезличенные образцы (Q23).
- **DeepSeek не принимает PDF**: PDF-документ при этом провайдере не распознаётся (ошибка в интерфейсе объясняет это). Нужны изображения/XLSX/CSV или OpenAI.
- **Передача данных за рубеж** (OpenAI — США, DeepSeek — КНР): юридическое заключение не получено (Q4). До реальных клиентских документов — только обезличенные образцы.
- Координат (OCR) нет: «источник» — цитата текста от модели, подсветки на изображении нет. Цитата не проверяется программно на присутствие в документе.
- Уверенность — самооценка модели, не калиброванная вероятность.
- Зависшие задачи (воркер упал посреди задачи) автоматически не подбираются: в интерфейсе через 90 с появляется подсказка, задачу можно отменить и повторить. Очередь «мёртвых» писем отдельно не разбирается.
- Лимит в сутки считается по организации, стоимость запросов не учитывается.
- Автоматический E2E не нажимает «Распознать» (платный вызов); путь «загрузка → воркер → провайдер» проверен вручную скриптами `backend/scripts/smoke_extraction.py` и `e2e_live.py`.
- CI на GitHub с шагом SeaweedFS ещё не запускался: проверится после отправки.
- Переводы uz/en мои, носитель не проверял.
- Изменения закоммичены локально, в GitHub не отправлены (в том числе срез 3.1).
