# Отчёт: срез 1.1 — регистрация, организация, вход, аудит, изоляция организаций

Дата: 2026-10-10. Среда проверки: сервер Ubuntu 26.04 (Docker 29.8, PostgreSQL 16 в контейнере); статические проверки — macOS, Python 3.12 (uv), Node 24.

## Что реально работает (проверено командами ниже)
- Регистрация и вход по email+паролю; сессии — cookie `HttpOnly; SameSite=Lax`, в БД только SHA-256 токена; пароли Argon2id; выход отзывает сессию.
- CSRF double-submit на мутирующих запросах после входа.
- Троттлинг входа: 5 неудач за 15 минут → 429 с `Retry-After`.
- Создание организации с `Idempotency-Key`: автор становится владельцем; организация, членство, аудит и ключ — в одной транзакции; повтор возвращает тот же результат; тот же ключ с другим телом → 422; параллельные одинаковые запросы создают ровно одну организацию (проигравшие получают 409 и повторяют).
- Список организаций пользователя, просмотр организации (право `org.read`); чужая и несуществующая организация неразличимы (404).
- Tenant isolation: RLS в PostgreSQL на `membership` и `audit_event` (роль приложения без BYPASSRLS, не владелец таблиц, `FORCE ROW LEVEL SECURITY`), контекст через `set_config(..., true)` на транзакцию.
- Аудит append-only: триггер блокирует UPDATE/DELETE даже суперпользователю; у роли приложения только SELECT/INSERT. Записаны: `auth.registered`, `auth.login`, `auth.login_failed`, `auth.logout`, `org.created`.
- Роли и права из матрицы Q8 заполнены миграцией (7 ролей, 5 прав); в этом срезе используется `org.read`.
- Единый формат ошибок, correlation-id (заголовок и логи), JSON-логи, `/health`, `/ready`, OpenAPI (`docs/api/openapi.json`).
- UI: вход, регистрация, создание организации, главная организации с переключателем и выходом; состояния loading / error / empty / success; адаптивная вёрстка.

## Что НЕ реализовано / ограничения
- Нет: участников и ролей в UI, приглашений, журнала аудита в UI, смены пароля, списка сессий, сброса пароля и писем, MFA. Redis не подключён (не нужен до этапа 3).
- Rate limit только на вход и только по email (злоумышленник может временно блокировать вход чужому email; лимита по IP нет).
- Регистрация сообщает, что email занят (перечисление email возможно); подтверждения email нет.
- Формат ИНН/СТИР проверяется предварительно (цифры, 9–14 знаков) — правила не подтверждены бухгалтером (Q9).
- Вёрстка на обычном CSS с токенами, не Tailwind (отступление от ADR-015, обратимо). Шрифт Inter не подключён (системный стек) — без внешних загрузок.
- Внешний вид не проверялся человеком или по скриншотам; E2E проверяет поведение и доступные имена элементов.
- Секреты окружения лежат только в `~/hisob-ai/.env` на сервере (права 600).
- Известная уязвимость сборки: postcss внутри Next 15.
- Изменения не закоммичены в git.

## Риски
Конкурентный проигрыш при одинаковом `Idempotency-Key` возвращает 409 вместо ответа победителя (клиент должен повторить). Контейнеры работают в режиме dev-стенда; TLS, бэкапы и мониторинг отсутствуют.
