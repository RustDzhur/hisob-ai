# Отчёт: срез 2.2 — контрагенты и общий каркас списков (этап 2)

Дата: 2026-10-10. Среда: сервер Ubuntu 26.04 (Docker, PostgreSQL 16); статические проверки — macOS.

## Что реально работает
- **Контрагенты**: создание, просмотр, частичное редактирование, архивирование и возврат из архива (удалить нельзя — на контрагента будут ссылаться документы). Поля: название, ИНН/СТИР, роли «покупатель/поставщик», адрес, телефон, email, заметка. Значения нормализуются (пробелы, email в нижнем регистре, пустое → не задано). Архивного контрагента нельзя править (409), читать можно.
- **Уникальный ИНН/СТИР в организации** (в т.ч. среди архивных): конфликт даёт 409 с названием контрагента, у которого этот ИНН (`counterparty_tin_taken` / `…_archived`); пустой ИНН допускается у многих; в другой организации тот же ИНН разрешён. Гонка двух одновременных создач с одним ИНН даёт ровно один успех. Формат ИНН — предварительный (цифры, 9–14), правила не подтверждены бухгалтером.
- **Общий каркас списков** (`platform/listing.py` + `DataTable` + `useListParams`): серверные поиск, сортировка по белому списку колонок, стабильная пагинация (page/page_size ≤100), общий формат ответа `{items,total,page,page_size}`; спецсимволы `% _ \` в поиске — обычные символы; недопустимая сортировка → 422 `invalid_sort`. Состояние списка хранится в адресной строке (страница, поиск, сортировка, фильтры) — ссылка воспроизводит вид, «Назад» работает. На телефоне строки — карточки, сортировка — отдельными элементами (заголовки таблицы там скрыты).
- **Фильтры**: роль (все/покупатели/поставщики), статус (активные/в архиве/все); поиск по названию, ИНН/СТИР, email, телефону с задержкой 300 мс.
- **UI** на трёх языках: список, боковая панель (drawer) создания/правки с inline-ошибками, подтверждение архивации, пустое состояние с действием, состояние «ничего не найдено», ошибка с повтором.
- **Права**: чтение — `catalog.read` (все роли), изменение — `catalog.manage` (владелец, админ, бухгалтер, менеджер продаж/закупок). **Аудит**: `counterparty.created/updated/archived/restored` с до/после; повторы без изменений не пишутся. **Изоляция**: RLS на `counterparty`, удаление строк приложению запрещено на уровне прав БД.

## Что НЕ реализовано / ограничения
- Поиск — `ILIKE` без индекса: на десятках тысяч контрагентов понадобится `pg_trgm` (этап 9).
- Нет импорта/экспорта контрагентов, объединения дубликатов, истории изменений в карточке (она есть в журнале аудита), прикреплённых файлов, договоров и банковских реквизитов (договоры — этап 3, банк — этап 6).
- Нет проверки по реестрам (налоговая, ЕГРЮЛ-аналог): внешние источники не подключены и не выдумываются.
- Роль «покупатель/поставщик» необязательна: контрагент может не иметь ни одной.
- Названия не проверяются на дубликаты (разрешены одинаковые названия с разными ИНН).
- Переводы интерфейса на uz/en мои, носитель не проверял. Внешний вид глазами не проверялся.
- Изменения закоммичены локально, в GitHub не отправлены.
