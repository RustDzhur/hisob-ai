# Срез 6.1 — банковские счета и импорт выписок

План этапа: [docs/10-stage6-plan.md](../10-stage6-plan.md). Спорные решения: R13 в [docs/09-open-questions-recheck.md](../09-open-questions-recheck.md).

## Что сделано
- **Банковские счета** организации (название, банк, номер счёта, валюта — только включённая в организации), архив, поиск; номер нормализуется (пробелы убираются, верхний регистр), уникален в организации.
- **Профиль импорта** (сопоставление колонок) хранится у счёта. **Форматы выписок конкретных банков не зашиты** — пользователь выбирает образец файла, система читает заголовки, пользователь указывает колонки даты, суммы (одна колонка со знаком **или** отдельные колонки прихода и расхода), валюты, назначения, номера, контрагента и ИНН; формат даты из явного списка, десятичный и тысячный разделители, кодировка (UTF-8/Windows-1251), разделитель CSV, строка заголовков, лист XLSX.
- **Предпросмотр** ничего не сохраняет: счётчики (строк, готово, уже есть, с ошибками), список ошибок по строкам с кодами и понятным текстом, образец нормализованных строк, признак «этот файл уже загружен».
- **Строгая нормализация**: дата только по выбранному формату (в XLSX даты-ячейки читаются как даты), сумма — только обычная десятичная запись по профилю (экспонента, мусор, не-ASCII цифры, лишние знаки сверх валюты — ошибка строки, а не догадка), ноль — ошибка, валюта из файла обязана совпасть со счётом, ИНН — только цифры. Файл целиком принимается **только без ошибок строк**, либо при явном «пропустить строки с ошибками».
- **Идемпотентный импорт**: тот же файл по счёту → 409 со ссылкой на прежний импорт; **перекрывающиеся выписки не создают дублей** (хэш строки по нормализованным полям); два одинаковых платежа в одном файле — две операции (порядковый номер повтора); параллельные загрузки того же файла → одна успешная; параллельные перекрывающиеся — каждая операция ровно один раз.
- **Операции выписки неизменяемы** в БД (суммы, даты, назначение, хэш; удалять нельзя), меняется только статус сверки; контрагент по ИНН связывается автоматически как подсказка.
- **Безопасность файлов**: проверка по содержимому (макросы XLSX, зашифрованные/подозрительно сжатые книги, бинарник под видом CSV, PDF и т. п. отклоняются), предел 5 МБ и 20 000 строк, исходный файл сохраняется в хранилище по хэшу.
- Права `bank.read/manage/import/reconcile`; интерфейс «Банк» (операции с фильтрами, счета, страница счёта с профилем, предпросмотром, загрузкой и историей), uz/ru/en, аудит `bank_account.*`, `bank_import.created`.

**Найдено проверками и исправлено**: на запись об импорте у роли приложения не было права UPDATE для счётчиков (500) — выдано с триггером, разрешающим менять только счётчики; в тестах найден и исправлен некорректный номер счёта.

## Что НЕ реализовано / ограничения
- **Нет форматов конкретных банков, нет интеграций** (этап 7: без официальной документации — `NOT_CONFIGURED`/`MOCK`). Только CSV/XLSX с профилем.
- Нет сверки (срез 6.2) и отчётов (6.3); статус операции пока всегда «не сверена».
- Нет остатков/сальдо по выписке и контроля непрерывности (сверки входящего/исходящего остатка выписки).
- Профиль одноколоночный по датам/суммам: нет составных дат и разных валют в одном файле.
- Идентификация «тот же платёж» в перекрывающихся выписках основана на совпадении нормализованных полей и порядка повторов; выписка, где порядок одинаковых строк изменился, может дать расхождение.
- Переводы uz/en мои, носитель не проверял.
- Изменения закоммичены локально.
