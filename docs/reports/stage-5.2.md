# Срез 5.2 — правила проводок и проводки по документам

План этапа: [docs/09-stage5-plan.md](../09-stage5-plan.md). Спорные решения: [docs/09-open-questions-recheck.md](../09-open-questions-recheck.md) (R7, R8 и Q9/Q26) — **бухгалтер должен проверить**.

## Что сделано
- **Правила проводок вводит бухгалтер, встроенных нет.** Правило: ключ, название, тип документа, период действия, строки «счёт — сторона (дебет/кредит) — сумма из документа». Источники суммы — только «итого», «налог» и «итого минус налог» **как напечатано в документе**; ставок налогов, округлений и расчётов по строкам в движке нет.
- **Сбалансированность проверяется символьно**: правило принимается, только если дебет равен кредиту при любых суммах документа (например, Дт итого / Кт итого минус налог / Кт налог). Несбалансированное правило не сохраняется.
- **Жизненный цикл**: черновик → «Утвердить» с **обязательным основанием** (кто и когда утвердил сохраняется) → «Вывести из действия». Утверждённое правило **неизменяемо** (в том числе на уровне БД: строки заморожены триггером; статус «утверждено» без основания БД не примет). Изменение — **новая версия** (копия-черновик); утверждение новой версии выводит прежнюю из действия. Черновик можно удалить.
- **Предложения по документу**: для утверждённого документа система показывает проводки по всем действующим утверждённым правилам этого типа документа и даты (суммы, основание правила, причины, почему провести нельзя: нет итога/налога/валюты и т. п.). Нулевые строки не проводятся.
- **Проведение — только человеком** (`accounting.post`). Суммы **пересчитываются на сервере** по правилу, клиент их не присылает. Проводка хранит документ-источник, правило и его версию. По паре «документ — ключ правила» действует одна проводка (параллельные запросы: ровно одна); после сторно документ можно провести заново; другие версии того же правила повтор не создадут.
- **Интерфейс**: вкладка «Правила» (список, редактор строк с индикатором баланса, утверждение с основанием, новая версия, вывод, удаление черновика), панель «Проводки по документу» в карточке документа, плашки «Документ-основание / Правило» в проводке; uz/ru/en; аудит `posting_rule.*`, `journal_entry.created_from_rule`.

Покрыто: «в системе нет правил»; валидация (несбалансированное, одна сторона, неизвестный тип документа, диапазон дат, групповой/архивный/чужой счёт, дубликат ключа, неизвестный источник суммы); жизненный цикл (основание обязательно, неизменяемость утверждённого в API и в БД, новая версия, один черновик версии, утверждение новой выводит прежнюю, вывод, удаление черновика); права (бухгалтер утверждает, аудитор читает, кладовщик не видит); предложения (неутверждённый документ, черновик правила не предлагается, суммы 1120/120 → 1120 / 1000 / 120, нулевой налог, налог не указан → причина); проведение (источник и версия в проводке, повтор и новая версия блокируются, после сторно можно заново, действие правила по датам, закрытый период, неверный тип, неутверждённое правило, права, изоляция организаций, **4 параллельных проведения → одно**); RLS на новых таблицах.

**Найдено проверками и исправлено**: при проведении по правилу источник и правило не записывались в проводку (повтор не блокировался) — поймано тестом параллельного проведения; на удаление черновика правила не хватало права DELETE у роли приложения (500).

**Честно про один сбой**: в полном прогоне один раз упал мобильный сценарий склада (`stock.spec.ts:73`, 16 с — таймаут под нагрузкой: диск ВМ сейчас на HDD, R9); при повторном прогоне файла 16 из 16 прошли. Причина — медленная среда, а не логика.

## Что НЕ реализовано / ограничения
- **Никаких готовых правил, счетов и налогов нет**; суммы только из «итого/налог» документа (R7). Нет правил по строкам документа, по контрагенту, по складским операциям (в складе нет стоимости).
- Утверждение правила — одним пользователем с правом `accounting.manage`, без второго согласующего (R8).
- Нет импорта правил/плана счетов, массового проведения нескольких документов, автоматического проведения (намеренно: проводит человек).
- Правило применяется по типу документа и дате; условий по сумме/валюте/контрагенту нет.
- Нет курсов валют (срез 5.3): проводка в валюте документа.
- Переводы uz/en мои, носитель не проверял.
- Изменения закоммичены локально, в GitHub не отправлены.
