# Срез 3.3 — сравнение провайдеров распознавания (ТЗ §14)

## Что сделано
Инструмент оценки `backend/scripts/eval_providers.py` + набор `backend/scripts/eval_dataset.py`. Провайдеры вызываются напрямую теми же адаптерами, входами, схемой и разбором, что и в боевом коде (без БД и очереди). Метрики: точность полей, доля ручных исправлений, ошибки с высокой уверенностью, калибровка уверенности, задержка, токены на документ, стоимость (если переданы цены). Формат набора (`manifest.json` + файлы + эталон) тот же для **реальных обезличенных образцов** (Q23): достаточно положить их в каталог и указать `--dataset`. Сама оценка проверена тестами (`tests/unit/test_eval_scoring.py`: нормализация, классы ошибок, лишние/недостающие строки).

## Набор (СИНТЕТИЧЕСКИЙ — все данные выдуманы, это не клиентские документы)
12 документов: чистый английский счёт; узбекский (латиница) с НДС; русский с пробелами и запятыми в суммах; русский с шумом и наклоном; USD с дробными количествами; чек без номера и единиц (проверка «не выдумывать»); счёт с вшитой инъекцией («ignore previous instructions…»); накладная на 9 строк; низкий контраст в JPEG; PDF-скан; CSV и XLSX на русском без итога. Каждый документ — 3 прогона на провайдера (36 вызовов). Модели: OpenAI `gpt-6-luna`, DeepSeek `deepseek-flash` (названия задал владелец).

## Что показали ошибки (это главное)
1. **Уверенность модели не отличает правильное от ошибочного.** Все ошибки пришли с уверенностью ≥ 0,85, средняя у ошибочных практически равна средней у верных. Значит, цветной индикатор уверенности в интерфейсе нельзя считать сигналом «проверьте это поле». Реальный защитный механизм — валидация и обязательная проверка человеком, а не confidence. В интерфейсе стоит переформулировать/приглушить этот показатель.
2. **Латинские и кириллические «двойники»**: оба провайдера вернули номер `TH-88` латиницей вместо `ТН-88` кириллицей (визуально неотличимы). Это ломает поиск дубликатов и сопоставление по номеру. Нужна нормализация таких символов при сравнении (не сделана).
3. **ИНН с лишней цифрой**: OpenAI дважды из трёх прочитал `300000111` как `3000000111` (повторяющиеся нули). Проверка длины ИНН (Q22) поймала бы это, но правило о длине я не вводил без вашего решения.
4. **DeepSeek возвращает тип документа свободным текстом** («СЧЁТ-ФАКТУРА», «HISOB-FAKTURA»), т.к. его JSON-режим не навязывает перечень значений. Наше приложение такие значения **отбрасывает** как невалидные (поле не заполняется), так что вреда нет, но тип у DeepSeek часто остаётся неопределённым. У OpenAI схема строгая — таких ошибок нет.
5. DeepSeek **не принимает PDF** (3 вызова из 36).
6. DeepSeek быстрее (3,6 с против 6,5 с) и использует меньше токенов.

## Вывод и честные ограничения
- На этом наборе **разницы в точности между провайдерами нет** (99,3 % и 99,0 % при 12 документах — разница в пределах шума). Рекомендация остаётся прежней: **OpenAI основной (строгая схема, PDF), DeepSeek запасной**, как вы решили.
- **Набор простой и синтетический**: чистый напечатанный текст одним шрифтом (Arial с моего компьютера, только для генерации; в репозиторий не входит), нет рукописного текста, печатей, фото под углом, многостраничных и плохих сканов. Реальные документы дадут заметно худший результат. **Окончательный выбор провайдера по этим цифрам делать нельзя** — нужны 10–30 ваших обезличенных образцов (Q23).
- Один запуск по 3 повтора; доверительных интервалов нет.
- Не измерены: false match rate сопоставления контрагентов/товаров (нужны реальные справочники), доля успешного импорта, бухгалтерские инварианты (проводок ещё нет), нагрузка (20 параллельных задач — ТЗ §14).
- **Стоимость в деньгах не посчитана**: цены за токены не зашиты в код (я не знаю актуального прайса и не выдумываю). Скрипт посчитает, если передать `--price-in-per-1m` и `--price-out-per-1m`; пришлите цены или запустите сами.
- Запуск стоил небольшого количества токенов обоих провайдеров (≈ 93 тыс. входных и ≈ 76 тыс. выходных суммарно на OpenAI+DeepSeek).

## Как повторить
```
docker compose run --rm --no-deps -e PYTHONPATH=/srv -v $HOME/eval-out:/out -v $HOME/eval-fonts:/fonts:ro worker \
  python scripts/eval_providers.py --out /out --font /fonts/font.ttf --repeat 3 [--dataset DIR]
```
Без `--font` изображения с кириллицей не создаются (только CSV/XLSX). Ключи берутся из окружения воркера и не печатаются.
