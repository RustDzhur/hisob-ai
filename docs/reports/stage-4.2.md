# Срез 4.2 — склад по документам, возвраты, сторно

План этапа: [docs/08-stage4-plan.md](../08-stage4-plan.md). По-прежнему только количества: стоимости и проводок нет.

## Что сделано
- **Операция по утверждённому документу**: на карточке утверждённого документа — «Оформить складскую операцию»: вы выбираете, что оформить (приход, расход, возврат поставщику, возврат от клиента) и склад, система создаёт **черновик** по строкам документа. Проводит человек (право `stock.post`); AI ничего не проводит. Документ без утверждения — 409.
- **Готовность строк**: у каждой строки должен быть товар, количество и единица, совпадающая с единицей товара. Иначе — 422 со списком «строка N: что исправить», ничего не создаётся. Строки-услуги в складской учёт не попадают; документ без товарных строк — отдельная ошибка.
- **Единицы (решение владельца, Q27)**: если товар заведён в «шт», а в документе «кг», нужно привести единицу **товара** к единице документа. Пересчёта и коэффициентов нет. Чтобы это не исказило остатки, **смена единицы товара блокируется, как только по нему есть движения** (409 `product_unit_locked`).
- **Защита от повторов**: по одному документу один вид операции — один раз (уникальный индекс в БД; 4 параллельных запроса → ровно один создаётся). Удалённый черновик освобождает документ; после сторно документ можно оформить заново.
- **Возвраты**: возврат поставщику уменьшает остаток, возврат от клиента увеличивает; доступны и вручную, и по документу.
- **Сторно**: проведённую операцию можно сторнировать один раз — создаётся новая проведённая операция с противоположными движениями, исходная остаётся в истории и помечается «Сторнирована», у сторно — «Сторно» и ссылка на исходную. Сторно сторно нельзя; сторно проходит ту же проверку остатков (приход 10 при остатке 6 сторнировать нельзя). 4 параллельных сторно → одно.
- **Интерфейс**: блок «Складские операции по документу» в карточке документа, баннеры «Документ-основание / Сторнирована / Это сторно», кнопка «Сторнировать» с подтверждением, новые виды в списках и форме; uz/ru/en; аудит `created_from_document` и `reversed`.

## Что НЕ реализовано / ограничения
- Нет инвентаризации, минимального запаса и резервов (срез 4.3), нет итогового экрана сверки по этапу.
- Документ при проведении складской операции **не меняет статус** (статусы документа POSTED/RECONCILED зарезервированы для учёта и сверки в этапах 5–6); связь видна в обоих местах по ссылкам.
- Дата сторно по умолчанию — сегодня (серверная дата UTC), её можно указать в API; в интерфейсе выбор даты сторно не вынесен.
- Частичное оприходование документа несколькими операциями не поддерживается как отдельная функция: черновик можно отредактировать (количества), но «остаток документа» не считается.
- Одна операция по документу — один склад (разные склады для разных строк — отдельными операциями вручную).
- Переводы uz/en мои, носитель не проверял.
