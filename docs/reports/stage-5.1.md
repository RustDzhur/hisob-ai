# Срез 5.1 — бухгалтерский движок (без встроенных правил)

План этапа: [docs/09-stage5-plan.md](../09-stage5-plan.md). Спорные решения записаны в [docs/09-open-questions-recheck.md](../09-open-questions-recheck.md) (R2, R3, R4 и Q9/Q26) — **бухгалтер должен их проверить**.

## Что сделано
- **План счетов**: иерархия, групповые счета (без проводок), архив/возврат, поиск и сортировка. **Предзаполненных счетов нет** — план вводит бухгалтер; классификации счетов (актив/пассив) в системе нет.
- **Периоды**: календарные месяцы создаются автоматически открытыми при первой проводке; закрытие и повторное открытие (право `accounting.manage`). Закрытый период блокирует проводку и сторно.
- **Проводки**: дата, валюта (включённая в организации), содержание, строки «дебет/кредит» (минимум две, ровно одна сторона в строке), сумма не точнее знаков валюты, сквозная нумерация без пропусков и дублей. Дебет = кредит проверяется в приложении **и триггером БД**.
- **Сторно**: новая проводка с противоположными сторонами; один раз; сторно сторно нельзя; в закрытый период нельзя.
- **Отчёты**: оборотно-сальдовая ведомость (входящее / обороты / исходящее по счетам, итог, признак равенства оборотов) и карточка счёта с нарастающим сальдо и пагинацией. Валюты не смешиваются (курсов и пересчёта нет).
- **Инварианты на уровне БД**: журнал и строки **только добавляются** (триггер, даже владельцу БД; роли приложения выданы только INSERT/SELECT); проводка без строк, несбалансированная, в закрытом периоде или с датой вне периода не сохраняется даже при вставке в обход приложения.
- Права `accounting.read/post/manage` (матрица — предложение R3), аудит, интерфейс uz/ru/en: вкладки «Проводки», «План счетов», «Периоды», «Оборотно-сальдовая».

## Проверки (реальные результаты)
| Проверка | Результат |
|---|---|
| pytest на сервере | **404 passed** (402 в полном прогоне + 2 исправленных теста перепроверены отдельно) |
| Playwright, desktop + Pixel 7, полный прогон | **84 passed** (5,7 мин) |
| vitest | 36 passed |
| ruff, mypy --strict, import-linter, eslint, tsc, pip-audit | без замечаний |

Покрыто: права 7 ролей; план счетов (дубли, циклы, архив, вложенность); проводки (баланс, архивный/групповой/чужой счёт, валюта, знаки валюты, float/экспонента, одна строка); многовалютность без смешения; периоды (закрытие, повторное открытие, идемпотентность); сторно; **параллельные проводки получают уникальные номера 1..N без пропусков, параллельные сторно — одно**; отчёты (входящее сальдо, обороты, кредитовое сальдо, нарастающий итог не зависит от страницы); неизменяемость, баланс, закрытый период и «без строк» на уровне БД; изоляция организаций и RLS.

**Найдено проверками и исправлено**: `SELECT … FOR UPDATE` по журналу требует права UPDATE, которого у роли приложения нет (500) — блокировка убрана, двойное сторно исключает уникальный индекс; параллельное сторно давало 500 вместо 409 (нарушение уникальности на первой вставке); проводка без строк сохранялась — добавлен отложенный триггер.

## Происшествие на сервере (не связано с кодом)
Во время работы виртуальная машина сервера зависла: пул `local-lvm` (70 ГБ) на хосте Proxmox заполнился на 100 % (диск ВМ 110 ГБ при толстом использовании). Машина была остановлена и запущена заново, **диск ВМ перенесён на хранилище `backup-storage` (HDD, 805 ГБ свободно)**, старый том удалён, пул свободен. Данные проекта сохранились (БД, файлы); Redis после жёсткой остановки пришлось «починить» (хвост журнала усечён; это очередь, потери данных нет). **Побочный эффект: диск ВМ теперь на HDD, полный набор тестов идёт ~35 минут вместо ~5.** Если нужно вернуть скорость, диск стоит перенести на SSD нужного размера (сейчас на SSD хоста всего 70 ГБ под пул).

## Что НЕ реализовано / ограничения
- **Нет плана счетов, шаблонов проводок, налогов, оценки запасов** — это решения бухгалтера (Q9/Q26); автоматических проводок по документам и складу ещё нет (срез 5.2).
- Нет импорта плана счетов из файла, закрытия года, сальдо с развёрнутой иерархией (итоги по группам счетов не считаются: ведомость на уровне проводимых счетов).
- Нет курсов валют и переоценки (срез 5.3).
- Периоды — календарные месяцы; другая разбивка (кварталы, произвольные) не поддержана (R2).
- В ведомости нет выгрузки в файл/печати.
- Переводы uz/en мои, носитель не проверял.
- Изменения закоммичены локально, в GitHub не отправлены.
