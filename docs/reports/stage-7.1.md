# Отчёт: срез 7.1 — интеграции (контракт, честные статусы, тестовый адаптер, журнал)

## Что сделано
- **Контракт адаптера** (`app/modules/integrations/adapters.py`): описание провайдера (код, вид, статус, получена ли документация, возможности), операция синхронизации с курсором, закрытый список кодов ошибок адаптера. Комментарий фиксирует, что будущий адаптер обязан описать auth, capabilities, pagination, rate limits, retries, webhooks, cursor, error mapping — только по официальной документации.
- **Реестр провайдеров** (честные статусы по ТЗ §11):
  - **Multibank, Faktura.uz, Didox — `NOT_CONFIGURED`**: официальной документации и тестовых доступов нет (Q12), адаптеров нет, возможности пусты, подключить и синхронизировать нельзя (`409 integration_not_configured`). Ни адреса, ни поля, ни права доступа не придумывались.
  - **Файлы (CSV/XLSX, PDF) — `AVAILABLE`**: это уже готовые загрузка выписок и документов; карточка ведёт в эти разделы.
  - **Тестовый адаптер — `MOCK`**: детерминированные «записи» с курсором (по 3 за запуск, всего 9), **ничего не пишет в учёт**; интерфейс прямо говорит, что данные ненастоящие.
- **Журнал синхронизаций** (миграция 0017): таблица запусков (провайдер, режим, курсор до/после, число записей, результат, код ошибки, кто запустил) — только добавление; `request_id` делает запуск повторяемым: повтор возвращает тот же запуск, курсор не двигается второй раз; параллельные запуски сериализуются блокировкой подключения (курсоры не теряются).
- Аудит `integration.enabled/disabled/sync`; RLS на обе таблицы; права `integrations.read` (владелец, администратор, бухгалтер, аудитор) и `integrations.manage` (владелец, администратор).
- **Интерфейс «Интеграции»**: карточки с честным статусом; у ненастроенных провайдеров **нет кнопок** (подключать нечего); кнопки тестового режима — только с правом управления; журнал запусков; uz/ru/en.

## Что НЕ реализовано / ограничения
- **Нет ни одной настоящей интеграции**: Multibank, Faktura.uz, Didox ждут официальную документацию и тестовые доступы (Q12).
- **Хранилища секретов нет**: ни один провайдер не принимает ключей; когда появится реальный адаптер — шифрование на сервере, секрет не возвращается клиенту (ТЗ §7). Не сделано намеренно, чтобы не создавать неиспользуемый код.
- Нет webhooks, фоновой периодической синхронизации и повторов по расписанию (retries/rate limits описаны в контракте как обязанность реального адаптера).
- Журнал показывает последние 50 запусков без постраничной навигации.
- Переводы uz/en мои, носитель не проверял.
