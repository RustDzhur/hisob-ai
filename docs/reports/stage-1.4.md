# Отчёт: срез 1.4 — три языка интерфейса (узбекский по умолчанию, русский, английский)

Дата: 2026-10-10. Среда: сервер Ubuntu 26.04 (Docker, PostgreSQL 16); статические проверки — macOS.
Решения владельца: интерфейс на **узбекском (по умолчанию), русском и английском**; базовая валюта — **сум (UZS)**, **мультивалютность нужна** (см. docs/06-stage2-plan.md).

## Что реально работает
- **Три языка во всём существующем интерфейсе**: вход, регистрация, организация, главная, участники, приглашения, журнал аудита, безопасность. Узбекский — латиница (`oʻ`, `gʻ`), язык по умолчанию для нового браузера.
- **Переключатель языка** на экранах входа/приглашения и в верхней панели приложения; выбор хранится в cookie `hisob_lang` (1 год, без персональных данных), сервер рендерит страницу сразу на нужном языке (`<html lang>`), мерцания языка нет.
- **Ошибки сервера переводятся по устойчивому коду** (`errors.<code>`), ошибки полей — по `details[].code` с параметрами (`{min}`, `{max}`); если код неизвестен клиенту, показывается сообщение сервера. Бэкенд теперь отдаёт `code` во всех ошибках полей (`password_too_short`, `email_taken`, `tin_invalid`, `unknown_role`, `date_range_invalid` и др.).
- **Даты и время** форматируются по языку интерфейса (`uz-UZ`, `ru-RU`, `en-GB`); события аудита — в часовом поясе организации.
- Названия ролей и типов событий аудита локализованы на клиенте по коду (серверные русские названия — запасной вариант).
- **Защита от пропусков**: словари `uz` и `en` типизированы по `ru` — отсутствующий ключ не скомпилируется; тест сверяет одинаковый набор ключей, отсутствие пустых строк и сохранность плейсхолдеров.

## Ограничения (важно)
- **Переводы на узбекский и английский сделаны мной и не проверены носителем.** Бухгалтерские и юридические термины (например, «STIR», «Audit jurnali», «Taklifnoma») нужно проверить у узбекоязычного бухгалтера/редактора до использования клиентами.
- **Узбекская кириллица не поддерживается** (только латиница) — отдельное решение, если нужна.
- Язык хранится только в браузере (cookie), не в профиле пользователя: на другом устройстве снова будет узбекский.
- Серверные сообщения об ошибках остаются на русском как запасной вариант; клиент показывает их, только если не знает код.
- Тексты, которые появятся позже (письма, PDF, отчёты, ответы AI), потребуют своей локализации на сервере — пока таких нет.
- Не проверялось: вёрстка на узбекском (строки местами длиннее русских), шрифт Inter не подключён (системный стек).
- Изменения коммитом не отправлены в GitHub (локальный коммит, push — по вашему слову).
