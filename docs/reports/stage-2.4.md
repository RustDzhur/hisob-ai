# Отчёт: срез 2.4 — склады. Этап 2 (справочники) завершён

Дата: 2026-10-10. Среда: сервер Ubuntu 26.04 (Docker, PostgreSQL 16); статические проверки — macOS.

## Что реально работает
- **Склады** (модуль `inventory`): создание, просмотр, частичное редактирование, архивирование и возврат. Поля: название, адрес, заметка. Название уникально в организации без учёта регистра, включая архивные (`warehouse_name_taken` / `…_archived`); в другой организации то же название разрешено. Архивный склад нельзя править (409), читать можно. Удалять склады нельзя (на них будут ссылаться движения).
- **Права**: `warehouses.read` — все роли; `warehouses.manage` — владелец, админ организации и **кладовщик** (бухгалтер, менеджер и остальные только смотрят; кладовщик при этом не управляет товарами/контрагентами).
- **Списки** на общем каркасе: поиск по названию и адресу, фильтр по статусу, сортировка по названию/дате, пагинация, состояние в URL.
- **Аудит** `warehouse.created/updated/archived/restored` с до/после; без записи при отсутствии изменений. **Изоляция**: RLS на `warehouse`, удаление запрещено правами БД.
- **UI** на трёх языках: страница «Склады», панель создания/правки, подтверждение архивации; пункт меню виден по праву `warehouses.read`, кнопки управления — по `warehouses.manage`.

- Правило «нельзя архивировать склад с остатками» появится на этапе 4 (остатков пока нет).
- Курсов валют и пересчёта нет (ждут утверждённых правил бухгалтера, Q6/Q9). Формат ИНН/СТИР и ИКПУ не подтверждены источником.
- Переводы на uz/en мои, носитель не проверял. Внешний вид глазами не проверялся; доступность (WCAG) инструментами не аудирована.
