# Отчёт: срез 1.2 — участники, приглашения, роли

Дата: 2026-10-10. Среда: сервер Ubuntu 26.04 (Docker, PostgreSQL 16); статические проверки — macOS (Python 3.12 через uv, Node 24).

## Что реально работает
- **Приглашение по ссылке** (почта не подключена, ссылка передаётся вручную): владелец/админ создаёт приглашение (email + роль), получает ссылку **один раз** (в БД только SHA-256 токена), срок 7 дней. Приглашённый открывает ссылку, входит или регистрируется (возврат на приглашение через безопасный `?next=`) и принимает; приглашение одноразовое.
- **Список участников** (право `members.read`), **смена роли**, **приостановка и возврат** (право `members.manage`), список действующих приглашений и **отзыв**.
- **Правила ролей**: `org_admin` не может приглашать/назначать владельцев и менять/приостанавливать владельцев; в организации всегда остаётся ≥1 активный владелец (блокировка строк владельцев `FOR UPDATE`, проверка под гонкой); нельзя приостановить самого себя; приостановленный не видит организацию (404), но может войти в аккаунт.
- **Права на сервере**: единая функция `authorize()` — членство → контекст RLS → право → аудит отказа (`access.denied`). Чужая организация и приостановленное членство неотличимы от несуществующей (404).
- **RLS**: таблица `invitation` с политиками по организации; доступ получателя к ровно одной строке — по владению токеном (`app.invite_token`).
- **Аудит**: `member.invited`, `member.joined`, `member.role_changed`, `member.suspended`, `member.reactivated`, `member.invitation_revoked`, `access.denied`.
- **UI**: страница «Участники» (таблица на десктопе, карточки на мобильном), форма приглашения со ссылкой и копированием, диалоги подтверждения для приостановки/отзыва, страница `/invite/<токен>`; пункт меню «Участники» виден только при праве `members.read`; кнопки управления — только при `members.manage`.
- Справочник ролей `GET /api/v1/roles`.

## Что НЕ реализовано / ограничения
- **Нет отправки писем**: ссылку передаёт человек. Повторно показать ссылку нельзя (токен не хранится): нужно отозвать и создать новое приглашение.
- **Удаления участника нет** — только приостановка (удаление необратимо и не заказывалось). Нет «выйти из организации».
- Матрица ролей и правило «админ не управляет владельцами» — моё предложение по Q8, подтверждено вами в общем виде; права модулей (документы, склад и т.д.) появятся вместе с модулями, поэтому у большинства ролей сейчас только `org.read`.
- `access.denied` пишется только при отказе в `authorize()` (прав организации); отказы 401/CSRF в аудит не пишутся.
- Приглашение можно принять только аккаунтом с тем же email (сравнение без учёта регистра); смены email у аккаунта нет.
- Просмотр журнала аудита в UI, смена пароля и сессии — срез 1.3.
- Сервер не ограничивает частоту создания приглашений (кроме уникальности «одно действующее на email»).
- Внешний вид глазами не проверялся, E2E проверяет поведение. Изменения не закоммичены.
