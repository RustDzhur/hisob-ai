# Отчёт: срез 3.1 — документы без распознавания (этап 3, начало)

Дата: 2026-10-10. Среда: сервер Ubuntu 26.04 (Docker, PostgreSQL 16, SeaweedFS 4.48); статические проверки — macOS.
Провайдер распознавания (OpenAI/DeepSeek) в этом срезе **не используется** и не нужен: распознавание — срез 3.2, ключи вы внесёте сами.

## Что реально работает
- **Загрузка файлов** PDF, JPEG, PNG, XLSX, CSV (несколько файлов подряд, перетаскивание, на телефоне — «Сфотографировать»). Тип определяется **по содержимому**, а не по расширению и не по заголовку клиента; расширение обязано соответствовать содержимому. Лимит 20 МБ (413 `file_too_large`).
- **Проверки безопасности вложений** (это не антивирус): PDF с активным содержимым (`/JavaScript`, `/JS`, `/Launch`, вложения, RichMedia) отклоняются; XLSX — без макросов, шифрования, путей `..`, «бомб» сжатия, с лимитами на число частей и распакованный размер; изображения проверяются декодером и ограничены по числу пикселей; CSV — текст UTF-8/Windows-1251 без управляющих символов; имя файла очищается от путей и спецсимволов и в ключ хранилища не попадает. Отклонённый файл документа не создаёт.
- **Хранилище**: S3-совместимое (SeaweedFS; MinIO больше не публикует образы) за интерфейсом `ObjectStorage`; ключ объекта — по содержимому (`организация/sha[:2]/sha256`). Скачивание — через API с проверкой прав, `X-Content-Type-Options: nosniff`, CSP, `Cache-Control: private, no-store`; каждое скачивание пишется в аудит.
- **Дубликаты**: одинаковый SHA-256 в организации не создаёт второй документ — 409 `document_duplicate` со ссылкой на имеющийся (даже если тот в архиве), попытка пишется в аудит; параллельная загрузка одного файла даёт ровно один документ; в другой организации тот же файл допустим. Проверяющий вручную помечает «это дубликат документа X».
- **Карточка документа**: оригинал (изображение или PDF) рядом с полями; тип, номер, дата, контрагент (поиск по справочнику), валюта (только включённые), итог, налог «как напечатано», заметка, **строки** (наименование, товар из справочника, единица, количество, цена, скидка, налог, сумма). Оптимистичная блокировка: правка устаревшей версии → 409 `document_conflict`, утверждать устаревшее нельзя.
- **Проверки**: *ошибки блокируют утверждение* (нет даты, номера, контрагента, итога, строк у документов со строками, валюты при наличии сумм; контрагент в архиве; валюта не включена; единица отключена). *Предупреждения требуют явного подтверждения*, которое фиксируется в аудите: расхождение суммы строки с «количество × цена − скидка», налога документа с суммой по строкам, итога ни с суммой строк, ни с суммой строк плюс налог (какой режим цен — неизвестно), возможный дубликат (тот же контрагент и номер), у контрагента нет ИНН, дата в будущем, строка без суммы, товар в архиве.
- **Статусы и действия**: `NEEDS_REVIEW → APPROVED / REJECTED (с причиной) / DUPLICATE`, возврат на проверку, архив/возврат из архива; недопустимые переходы — 409. Утверждение и снятие утверждения — право `documents.approve`, остальное — `documents.review`.
- **Права**: `documents.read/upload/review/approve` (матрица в `docs/07-stage3-plan.md`, Q21). **Аудит**: `document.uploaded / duplicate_upload / file_downloaded / updated (до/после) / approved (с принятыми предупреждениями) / rejected / marked_duplicate / reopened / archived / restored`. **Изоляция**: RLS на `document`, `document_file`, `document_line`; составные внешние ключи не дают связать документ, строку или файл с контрагентом, товаром или документом другой организации даже в обход приложения; удалять документы и файлы приложению запрещено правами БД.
- **UI** на трёх языках: список (поиск, фильтры статус/тип, сортировка, пагинация), загрузка, карточка проверки, окна утверждения (с галочками по предупреждениям), отклонения, пометки дубликата.

## Что НЕ реализовано / ограничения
- **Распознавания нет**: поля вводятся вручную (срез 3.2: OpenAI/DeepSeek, очередь, confidence и источник полей, сопоставление). Статусы обработки (QUEUED…MATCHING) заложены в БД, но не используются.
- **Антивируса нет**: проверки структурные (эвристики); обфусцированные имена в PDF (`#4A`) они не поймают. ClamAV и т.п. — этап 9.
- Предпросмотр PDF в автоматических тестах не проверялся визуально (в headless нет PDF-просмотрщика): проверено наличие элемента; для PDF CSP-`sandbox` не ставится (он ломает встроенный просмотр), для остальных типов ставится. **Просмотрите PDF в обычном браузере.**
- Один файл на документ; нет нескольких версий файла, поворота/кадрирования изображений, подсветки фрагмента (нужны координаты OCR — 3.2).
- Дубликаты ловятся по содержимому файла и подсказкой «тот же контрагент и номер»; различающиеся сканы одного документа так не найти.
- Допуск при сравнении сумм (0,5 минимальной единицы валюты на слагаемое, не меньше одной) — **предварительный порог**, а не правило округления (Q6/Q9). Налоги не вычисляются.
- Нет импорта строк из XLSX/CSV, экспорта, связей документов между собой (`DocumentRelation`), утверждённый документ пока ни к чему не «проводится» (склад — этап 4, учёт — этап 5).
- Осиротевшие объекты в хранилище возможны, если коммит БД сорвался после записи файла (ключ по содержимому, повторная загрузка безвредна; чистка — этап 9).
- Мобильная карточка документа: таблица строк прокручивается по горизонтали (редактирование большого документа удобнее на компьютере).
- Переводы на uz/en мои, носитель не проверял; доступность (WCAG) инструментами не аудирована.
- Полный E2E-прогон занимает ~4 минуты; один тест товаров был нестабилен под нагрузкой — ожидания увеличены до 10 с (затем 3 полных прогона без сбоев).
- GitHub Actions обновлён (поднимает SeaweedFS для тестов), но **на GitHub этот вариант ещё не запускался**: проверится после отправки.
- Изменения закоммичены локально, в GitHub не отправлены.
