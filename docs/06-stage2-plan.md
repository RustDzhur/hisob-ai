# План этапа 2 — справочники

> Статус: срезы 2.1 (`docs/reports/stage-2.1.md`) и 2.2 (`docs/reports/stage-2.2.md`) реализованы; каркас списков (бывший 2.0) построен в 2.2 вместе с контрагентами. Дальше — 2.3 (товары и услуги), 2.4 (склады).

Основание: ТЗ §4 («Контрагенты», «Товары и услуги», «Склад»), §7 (сущности), этап 2 в `docs/05-roadmap.md`. Решения владельца от 2026-10-10: базовая валюта **UZS**, **мультивалютность нужна**, интерфейс **uz (по умолчанию) / ru / en**.

## 1. Принципы мультивалютности (что фиксируем сейчас, что — нет)
**Фиксируем:**
- Любая сумма хранится как `NUMERIC` вместе с кодом валюты (`CHAR(3)`), валюта никогда не «подразумевается».
- Справочник валют (глобальный): код ISO 4217, число знаков после запятой, названия на uz/ru/en. Стартовый набор — **UZS, USD, EUR, RUB, KZT, CNY** (реальные коды; остальные добавляются по запросу). У организации — список включённых валют; базовая (по умолчанию UZS) всегда включена и не отключается.
- Цена товара и реквизиты контрагента могут быть в любой включённой валюте организации.
- Арифметика между валютами **запрещена без явной записи курса**: пересчёта «на лету» по чужим данным нет.

**Не делаем в этапе 2 (нет утверждённых правил — не выдумываем):**
- Курсы валют и пересчёт: источник курса (например, официальный курс ЦБ), на какую дату брать, правила округления (Q6) и курсовые разницы определяет бухгалтер (Q9). Модель `exchange_rate (organization, from, to, date, rate NUMERIC, source, created_by)` проектируем вместе с этапом 5, ввод курсов вручную — не раньше.
- Обращение к внешним сервисам курсов: интеграции подключаются только по официальной документации (ADR-013).

## 2. Срезы этапа 2 (каждый — вертикальный: БД → API → UI → тесты → отчёт; пауза после каждого)
| Срез | Содержание | Ключевая приёмка |
|---|---|---|
| 2.0 | Общий каркас списков: серверная пагинация/поиск/сортировка (единый формат), компонент `DataTable` (состояния loading/empty/error, мобильные карточки), права `catalog.*` | один и тот же механизм для всех справочников; тест на параметры и границы |
| 2.1 | Валюты организации (включить/отключить, базовая закреплена) + единицы измерения | база нельзя отключить; изоляция; аудит |
| 2.2 | Контрагенты (создание, правка, архивирование; поиск; уникальный ИНН/СТИР в организации; роли покупатель/поставщик) | дубликат ИНН → 409 с понятным сообщением; архивированный не пропадает из истории; RLS и cross-tenant тесты |
| 2.3 | Товары и услуги (SKU, штрихкоды, единицы, цена в валюте, тип товар/услуга) | уникальность SKU/штрихкода в организации; цена — NUMERIC + валюта; Decimal в API строкой |
| 2.4 | Склады (создание, архив, адрес) | уникальное имя в организации; нельзя архивировать склад с остатками (появится на этапе 4 — пока заглушки нет, правило добавляется там) |

Все изменения справочников аудируются (до/после), все списки — с поиском, фильтрами, сортировкой и пагинацией (ТЗ §4), все тексты — на трёх языках, ошибки — по кодам.

## 3. Модель (набросок, уточняется перед каждым срезом)
- `currency(code PK, minor_units, name_uz, name_ru, name_en)`; `organization_currency(organization_id, currency_code, enabled_at)`.
- `unit_of_measure(id, organization_id, code, name, is_active)` — единицы организации; стартовый набор без официальных кодов (шт, кг, г, л, м), поле `official_code` пустое — **классификаторы (ИКПУ, коды единиц) не выдумываются**, вводятся вручную или после подтверждения источника.
- `counterparty(id, organization_id, name, tin NULL, is_customer, is_supplier, address, phone, email, notes, archived_at, UNIQUE(organization_id, tin) WHERE tin IS NOT NULL)`.
- `product(id, organization_id, kind[goods|service], sku, name, unit_id, price NUMERIC NULL, price_currency NULL, ikpu NULL, archived_at)`, `product_identifier(product_id, kind[barcode|…], value, UNIQUE(organization_id, value))`.
- `warehouse(id, organization_id, name, address, archived_at)`.
- Все — с `organization_id`, RLS-политиками как в `membership`, тестами изоляции.

## 5. Открытые вопросы
- **Q14.** Подтверждаете стартовый набор валют (UZS, USD, EUR, RUB, KZT, CNY)? Нужны ли другие с самого начала?
- **Q15.** Матрица прав §4 — подтверждаете или меняете (особенно `catalog.manage` для менеджера и склад для кладовщика)?
- **Q16.** Контрагенты: нужны ли поля помимо перечисленных (банковские реквизиты, ОКЭД, ответственное лицо, договоры)? Банковские реквизиты предлагаю отложить до этапа 6 (банк), договоры — до этапа 3 (документы).
- **Q17.** Единицы измерения: есть ли требуемый классификатор/список единиц, который нужно загрузить (вместо ручного ввода)? Источник должен быть официальным.
- **Q18.** Узбекский: подтверждаете латиницу как единственное письмо; кто проверит переводы (Q7)?
- Не блокируют: Q4, Q6, Q9, Q10, Q12 (см. `docs/05-roadmap.md`) — они нужны этапам 3–7.
