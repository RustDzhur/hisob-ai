# План этапа 9 — hardening

Основание: ТЗ §13 (безопасность и эксплуатация), §14 (нефункциональные требования), `docs/05-roadmap.md` (нагрузка, backup/restore, мониторинг, UAT, rollback).

## Срезы
| Срез | Содержание | Проверка |
|---|---|---|
| **9.1** | Защитные заголовки (API и фронтенд, CSP), ограничение частоты запросов (Redis, при сбое Redis — пропуск), аудит выгрузок CSV | тесты заголовков, лимитов по актору и по IP, «пропуск при сбое хранилища», аудит 4 выгрузок без содержимого |
| **9.2** | Метрики Prometheus (`/metrics` по токену), расширенный `/ready`, резервная копия и **проверка восстановления** (скрипты), нагрузочный тест, документ «Эксплуатация» (RPO/RTO — предложение, откат, хранение данных, инциденты, мониторинг, UAT) | реальный прогон резервной копии и восстановления на сервере с инвариантами; нагрузочный прогон с цифрами |
| 9.3 | Двухфакторная защита (TOTP) для пользователей, политика «обязательна для владельцев и администраторов» включается настройкой | тесты входа с кодом, кодов восстановления, шифрования секрета |

## Чего этап НЕ делает
Не заявляет соответствие требованиям (compliance) — это решает профессиональная проверка (ТЗ §13); не настраивает внешний мониторинг и оповещения (нужна площадка эксплуатации); не копирует резервные копии за пределы сервера (нужен внешний носитель/облако — решение владельца); не задаёт SLA/RPO/RTO — предлагает значения на утверждение (R17).
